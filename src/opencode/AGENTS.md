# src/opencode

## Purpose

OpenCode lifecycle management: install detection, installation, server start/stop/restart, and health polling. All terminal interaction is delegated through `../terminal/executor.ts`.

## Ownership

Owned by the root AGENTS.md. Nine export modules:
- `install.ts` — `checkInstalled()`, `installOpenCode()`, `uninstallOpenCode()`
- `health.ts` — `probeServer()`, `isServerUp()`, `isServerDownConfirmed()` (version-aware OpenCode API probe)
- `server.ts` — `buildStartCommand()`, `startServer()`, `waitForReady()`, `stopServer()`, `restartServer()`, `getServerPassword()`, `isV2Server()`
- `auth.ts` — `generatePassword()`, `buildAuthTokenUrl()`, `buildAuthTokenUrlFor()`, `buildBasicAuthHeader()`, `getInstalledMajor()`, `needsPairing()` (V2 password + auth_token iframe sign-in)
- `remote.ts` — `parseRemoteHost()`, `buildRemoteIframeUrl()` (remote OpenCode server address parsing)
- `update.ts` — `checkForUpdates()`, `installUpdate()`, `getInstalledVersion()` (npm version check + install, V2 track)
- `npm.ts` — `selectNpmCommand()` (probes `npm -v`, picks the install command)
- `version.ts` — `parseVersion()`, `compareVersions()` (shared semver-ish helpers)
- `diagnostics.ts` — `getRuntimeVersions()` (node/npm versions for the error view)

## Local Contracts

- `checkInstalled()` runs `which opencode` and returns boolean — errors mean not installed.
- `installOpenCode()` runs three sequential commands: install deps (`apk add nodejs npm`), probe npm (`npm -v`), then the npm install command chosen by `selectNpmCommand()`. Installs the V2 `@opencode/cli` package. Accepts an optional `onProgress` callback — when provided the deps and install steps execute via `executeVerbose()` (real-time stdout streaming) while the silent version probe always uses the blocking `execute()`; callers that don't need live feedback (tests) call without args and use the backward-compatible `execute()` path. On failure, throws `Error` with distinct prefixes — `"Installation failed (deps): "` or `"Installation failed (opencode): "` — followed by the captured error message and command output. The version probe cannot fail the install (see `selectNpmCommand()`).
- `uninstallOpenCode()` runs `npm uninstall -g opencode-ai @opencode/cli` (both the V1 and V2 packages, so reinstalls and V1→V2 migrations never leave the old package behind). On failure, throws `Error` with prefix `"Uninstallation failed: "` followed by the captured error message.
- `selectNpmCommand(allowScriptsCommand, fallbackCommand)` (in `npm.ts`) runs `NPM_VERSION_COMMAND` (`npm -v`) and returns `allowScriptsCommand` when the parsed version is `>= NPM_ALLOW_SCRIPTS_MIN_VERSION` (currently `11.16.0`), else `fallbackCommand`. Never rejects: a failed probe, unparseable output, or an older npm all fall back, so install/update is never blocked by the check. Used by both `installOpenCode()` and `installUpdate()`; the probe runs after the deps step because that step is what installs npm.
- `parseVersion()` / `compareVersions()` (in `version.ts`) are the shared semver-ish helpers used by `npm.ts` and `update.ts`. `compareVersions(left, right)` returns negative/zero/positive and treats missing parts as 0 ('11.16' === '11.16.0').
- `getRuntimeVersions()` (in `diagnostics.ts`) runs `NODE_VERSION_COMMAND` and `NPM_VERSION_COMMAND` in parallel and returns `{ node, npm }` — raw output (`'v26.8.2'`, `'11.19.1'`) or `VERSION_UNKNOWN` (`'?'`) per field. Never rejects and is bounded by `RUNTIME_VERSION_PROBE_TIMEOUT`, so a hung terminal resolves to `?` instead of stalling. Called fire-and-forget by `main.ts` after an error renders; `setErrorVersions()` in `ui/index.ts` fills the error view with the result.
- `probeServer(options?)` (in `health.ts`) identifies an OpenCode server through its API and reports exactly what it found: `'up'`, `'unauthorized'` (the V2 API's `401` challenge — still an OpenCode server), `'inconclusive'` (something answered, but not in a way that identifies OpenCode) or `'down'` (nothing is listening). It uses `cordova.plugin.http` (Cordova Advanced HTTP). `cordova.plugin.http` runs on the native network stack, so WebView CORS does NOT apply and the loopback probe actually resolves (a plain `fetch` to `127.0.0.1` hangs forever in this WebView). The probe walks two API surfaces in order and stops at the first answer that identifies OpenCode: `/api/config` (the V2 API root — answers JSON when the request carries valid basic auth and `401` when it does not) and `/global/health` (the V1 health route — answers `{"healthy":true,...}` as JSON). Every unknown path on both servers falls back to the SPA shell (HTML), so a JSON body or a `401` challenge is what identifies OpenCode; an HTML body means "something else answered on this port" and the probe moves on. A non-positive status (connection refused) or a probe timeout ends the run as down without trying the next surface. `options.password` (the plugin-managed V2 password) adds an `Authorization: Basic` header to the API probe so the answer is a readable JSON body instead of a `401`. `options.baseUrl` points the probe at another server (the remote host); it defaults to the plugin's own loopback server. The promise never rejects (bounded by an independent watchdog). Returns `'down'` immediately when `cordova.plugin.http` is absent. There is no `fetch` fallback.
- `isServerUp(options?)` (in `health.ts`) is the boolean view of `probeServer()`: `'up'` and `'unauthorized'` both mean "a server is listening" (the `401` challenge proves an auth-walled OpenCode server is there), everything else is not up.
- `isServerDownConfirmed(options?)` (in `health.ts`) confirms a Ready-state crash by probing with `isServerUp()` up to `HEALTH_CRASH_CONFIRM_ATTEMPTS` (currently `3`) times, spaced by `HEALTH_CRASH_RETRY_INTERVAL`. Returns `true` only when every probe reports down; a single up means the earlier miss was transient. Never rejects. Called by `main.ts` on each `HEALTH_PROBE_INTERVAL` tick instead of a single `isServerUp()` check.
- `parseRemoteHost(value)` (in `remote.ts`) parses the `remoteHost` setting into a validated `{ baseUrl, host, port, secure }` remote server. Accepted shapes: `host`, `host:port`, `scheme://host`, `scheme://host:port` and bracketed IPv6 literals (`[::1]:4096`); a value without a scheme is plain HTTP, and the scheme's default port applies when the value omits one (4096 for HTTP, 443 for HTTPS). Returns null for anything empty, malformed or out of range — the caller reports the invalid-host error instead of connecting to a bogus URL. The remote host is user input, so nothing derived from it is used before it validates.
- `buildRemoteIframeUrl(baseUrl, password)` (in `remote.ts`) returns the sign-in URL for a remote server (`buildAuthTokenUrlFor()`) when the password is known, and the plain base URL otherwise (manual login in the web UI).
- The Ready crash detector (`main.ts`) carries an epoch token: every `stopHealthProbe()` bumps the epoch, each interval tick captures it before probing and ignores its result when the epoch moved (stop/restart/reinstall happened mid-check) or the state left `Ready`. Ticks never overlap (an in-progress guard skips re-entrant ticks). `handleStop()` stops the probe before awaiting `stopServer()` so shutting down on purpose never reports a crash.
- `startServer()` detects the installed major version via `getInstalledMajor()` (auth.ts), then launches `opencode serve ...` via `startProcess()` from the terminal executor module, which wraps the foreground `Executor.start()` and returns a `ProcessHandle` with a UUID. The foreground executor is what keeps the server alive when Acode leaves the foreground (the background executor's processes are killed by Android). The UUID is stored in a module-level `serverUuid` variable. On V2 (major >= `V2_MAJOR_VERSION`, or unknown — secure default) it generates a per-launch password via `generatePassword()` and prefixes `OPENCODE_SERVER_PASSWORD=<pw>` onto the command; on V1 it launches without auth (legacy behavior). The password is memory-only (never persisted) and cleared on stop and on launch failure; `getServerPassword()` / `isV2Server()` (true only for a plugin-managed V2 server) expose it for the pairing flow. No immediate crash check — if the process exits prematurely, it will be detected naturally by `waitForReady()` timing out. Server stdout/stderr lines are accumulated in a configurable ring buffer (`SERVER_LOG_LINES`, currently 40) for diagnostics. Lines starting with a `SERVER_LOG_NOISE_PREFIXES` entry (`proot warning:` container noise) are dropped before buffering; `proot info:` lines are kept.
- `getServerLog()` returns the current ring buffer contents as a string — used for error diagnostics both when `waitForReady()` times out and when the Ready crash detector (`isServerDownConfirmed()` via `main.ts`) confirms the server is down, so the error view carries `HEALTH_CONNECTION_LOST_MESSAGE` plus the last N lines instead of an empty detail.
- `waitForReady()` polls `isServerUp({ password: serverPassword })` every `READY_POLL_INTERVAL` ms until `READY_TIMEOUT`. On timeout, checks process state via `PROCESS_CHECK_COMMAND` and throws an `Error` that includes process state (alive/dead/unknown).
- `stopServer()` calls `stopBackground(serverUuid)` (the terminal executor wrapper) to gracefully stop the server process. Polls `isServerUp({ password: serverPassword })` for up to `STOP_POLL_TIMEOUT`; if still up, falls back to `pkill -9` (SIGKILL) and polls again. Throws `Error` if port is still occupied after SIGKILL. Resets `serverUuid = null` on successful shutdown and clears the stored password/version via `clearServerAuth()`.
- `restartServer()` is stop → start sequential, no concurrent semantics.
- `checkForUpdates()` (in `update.ts`) runs `opencode --version` and `npm view @opencode/cli version` in parallel, parses both outputs for semver-like patterns, and returns `{ currentVersion, latestVersion }` when latest > current. V1 installs compare against the V2 track, so the update button migrates V1→V2 in a single press. The promise never rejects: all errors (binary not found, npm unreachable, parse failure) are caught, logged, and return null. Designed as fire-and-forget from `AcodePlugin.init()`.
- `installUpdate()` (in `update.ts`) best-effort removes the legacy V1 package via `UNINSTALL_V1_COMMAND` (failures ignored — the package may not be installed), then runs the command chosen by `selectNpmCommand()` — `INSTALL_UPDATE_COMMAND_ALLOW_SCRIPTS` on npm >= the minimum, `INSTALL_UPDATE_COMMAND` otherwise — via the Alpine terminal. Unlike the uninstall step, the install **throws** on failure so the caller (`AcodePlugin.handleUpdateClick()`) can transition to an error state in the UI.
- All command **string constants** are defined in `src/config/` (e.g. `opencode.ts`, `server.ts`, `health.ts`, `update.ts`, `auth.ts`). The `buildStartCommand(password)` builder (server-launch assembly) lives in `server.ts` because it is server-start logic and the sole consumer; `startServer()` calls it rather than inlining the raw shell command. Never inline raw shell strings in `server.ts`. The password is set via `env(1)` (`env OPENCODE_SERVER_PASSWORD=<pw> opencode serve ...`), not a shell `VAR=x` prefix — the Executor hands the command to the Alpine launcher without shell assignment parsing (a `VAR=x` prefix dies with "not found" / exit 127).
- `getInstalledVersion()` (in `update.ts`) probes `opencode --version` and returns the parsed version or null; never rejects. Used by `main.ts` to refresh the update banner to the newly installed version after an update (the pre-update info would show the stale old version).
- `auth.ts` owns the V2 sign-in flow with no UI involvement: `generatePassword()` (hex from `crypto.getRandomValues`, `PASSWORD_BYTE_LENGTH` bytes), `buildAuthTokenUrl()` (`BASE_URL` + `?auth_token=<base64url(user:password)>`, which the SPA reads, scrubs from the address bar, and holds in memory for Basic-auth API calls — no cookie, no mint round-trip), `buildAuthTokenUrlFor(baseUrl, password)` (same token pointed at an arbitrary base URL — used for remote servers the plugin does not start), `buildBasicAuthHeader()` (`Basic <base64(user:password)>`, standard base64 — used by the health probe to read the V2 API instead of the `401` challenge), `getInstalledMajor()` (version-branch probe, never rejects, null on failure), and `needsPairing()` (null/unknown counts as V2). `main.ts` resolves the Ready iframe URL synchronously (`resolveIframeUrl()`: token URL when it holds a server password, else `BASE_URL`) after every self-started launch, and via `resolveAlreadyRunningUrl()` for already-running servers — reusing a held/entered password or prompting once with the native dialog (`promptServerPassword()`, cancel degrades to `BASE_URL` manual login). The entered password lives in `main.ts` only (`enteredPassword`, cleared on stop, never persisted).

## Work Guidance

- Add new lifecycle stages by exporting a function, not by inlining logic in `main.ts`.
- The health probe lives in `health.ts` and uses `cordova.plugin.http` (bypasses WebView CORS and resolves on loopback). There is no `fetch` fallback — do not reintroduce one; a plain `fetch` to loopback hangs in this WebView. Keep the probe surfaces in sync with the server: `/api/config` for V2, `/global/health` for V1, and never accept an HTML body as proof that OpenCode is running.
